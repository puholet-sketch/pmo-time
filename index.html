Учёт времени, который сходится с табелем

Плейбук проектного офиса: куда списывать часы в Jira, кто заводит Epic, как связаны оценка, реализация, SLA и контроль план/факт — без разрозненных Excel и «устных» правил.

Смотреть схемы Правила списания

Для команд, где уже есть Jira, но факт часов не стыкуется с бюджетом Epic, табелем и отчётами руководству. Обобщённый консалтинг-кейс по живой практике PMO (без привязки к конкретному работодателю).

Модель в Jira

Одна иерархия для всех контуров. Часы почти всегда живут в Subtask; Epic держит план и закрытие.

Epic
бюджет · план · тип работ
→
Story
единица функционала / заявки
→
Subtask
сюда списывает исполнитель

ПМ / ГРП

Story и Subtask, оценка, приёмка, уведомления финансам и аккаунту.

Финансы

Регистрация Epic по заявке, связь с договором, отчёты и сверка с табелем.

Исполнитель

Log Work в своём Subtask: затрачено, осталось, комментарий, день факта.

ОД / ТД

Мониторинг план/факт по периоду, проекту и эпику.

Контуры учёта

Шесть рабочих контуров вместо десятка разрозненных разделов. Логика одна: заявка → согласование → Epic → работы → факт → закрытие.

01

Годовое планирование

Оценки, SLA-сервис, собеседования, косвенные затраты тимлидов, простои/совещания, управление подразделениями — один шаблон запуска Epic.

02

Фикс. бюджет

Оценка → согласование → Epic реализации → перенос Story → приёмка клиентом → акты.

03

Оценка в Jira

Story оценки + Subtask типа «Оценка»: предмет, декомпозиция, суммарная оценка, фактические часы.

04

SLA / поддержка

1-я линия закрывает консультацию в Issue; эскалация — Issue в Epic сервиса + Subtask на 2-й линии.

05

Presale · HR · прочее

Presale и обучение — отдельный Epic; собеседования — Story; простои/митинги — выделенные Story в годовых Epic.

06

Контроль

Ежемесячный отчёт по Epic, еженедельный список «должников» по списаниям, сверка Jira ↔ табель.

Ключевые схемы

Четыре потока вместо длинных sequence на каждый подраздел. Участники — роли, не фамилии.

1. Универсальный запуск годового Epic

Одинаково для оценок, SLA-бюджета, собеседований, тимлид-косвенных и т.п. — меняются только инициатор, согласующий и тип Epic.

Коротко про остальные контуры

Presale

Аккаунт → КД → финансы регистрируют Epic (Presale) → ПМ ведёт Story/Subtask → приёмка аккаунтом → закрытие Epic.

Собеседования

HR определяет участников → рук. подразделения создаёт Story и Subtask → участники списывают время.

Обучение

Наставник согласует с рук. → Epic (Training) → Story/Subtask → факт часов → закрытие.

Простои / митинги

Сотрудник → рук. → Subtask в Story Downtime/Meeting → списание → закрытие Subtask.

Правила списания

Минимальный набор, без которого план/факт и табель расходятся.

  1. Списывать в Subtask внутри Epic Исключение: ошибка приёмки — допускается списание прямо в Issue.
  2. Затрачено — на день фактической работы Не «пачкой в пятницу задним числом без даты факта».
  3. Всегда: осталось + комментарий Комментарий описывает сделанное; «осталось» держит прогноз.
  4. Сумма списаний за день ≥ табеля Иначе еженедельный список должников и ручная сверка в конце месяца.
  5. Epic регистрируют финансы По заявке с трудоёмкостью и привязкой к проекту/договору. Нет проекта в Jira — сначала заявка на создание проекта.
  6. План на Epic, факт по Subtask Отчёты и мониторинг ОД/ТД читают эту связку, а не «среднюю температуру» по людям вне эпиков.
